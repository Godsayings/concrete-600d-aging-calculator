# 600℃·d 结构实体检验温度记录 —— 龄期、累计温度与等效龄期计算表

围绕《表 C5-19-1 600℃·d 结构实体检验温度记录》与
《表 C5-19-2 600°C·d 实体检验等效龄期计算表》的一组自动核算工具。

| 命令 | 作用 |
|---|---|
| `c600d aging` | 重算温度记录台账里的**龄期(d)** 与**累计温度(℃·d)** |
| `c600d eqage` | 从试验台账汇总生成**等效龄期计算表**（表 C5-19-2）工作表 |

两者默认都**只核算打印**，加 `--write` 才修改文件（并支持自动备份）。

## 为什么需要它

这两类表格手工维护时很容易出错，而且都不容易发现：

| 典型问题 | 现象 | 后果 |
|---|---|---|
| 累计温度按数据块重新起算 | 跨块/跨表累计值接不上 | 600℃·d 达标日算错 |
| 龄期列从别的工程抄来 | 龄期突然回跳 | 之后所有龄期都错 |
| 负温日照常累加 | 累计值倒退 | 与检验资料对不上 |
| 数值打了错字 | 如 1166.2 写成 116.2 | 偏差几百 ℃·d |
| 公式单元格没有缓存值 | 打开显示空白/0 | 看起来像没填 |
| 新楼栋要建表时逐格复制 | 漏改标题/列宽/合并区 | 表格不合规 |

## 计算口径

### 龄期(d)

自起算日（**浇注日计为第 1 天**）起的自然日差 + 1：

```
龄期(d) = (当日日期 - 起算日).days + 1
```

### 累计温度(℃·d)

```
累计温度(n) = 累计温度(n-1) + MAX(日平均温度(n), 0)
```

即 **T > 0 时累加当日平均温度；T ≤ 0 时按 0 计**。累计值单调不减，不会因负温日倒退，
符合冬期施工连续测温台账的通行做法。

> 这条口径不是拍脑袋定的：对真实工程台账做逐日回归后发现，账内累计值的偏差
> **每次增大都恰好发生在平均温度 ≤ 0 的那一天，且增大值恰好等于该日温度的绝对值**
> （抽验 294 个日增量：冻结口径符合 40/41 处，累加负温口径符合 253/256 处）。
> 改用该口径重算后，算出的 600℃·d 达标日与该工程检验资料中的等效龄期相互吻合。

### 写入方式

每列只把**第一格**写成数值，其余全部写成公式，保证全表一条链：

```
同表相邻行   =J19+MAX(F20,0)        （累计温度）
             =M19+1                 （龄期）
跨表相邻行   =Sheet1!J27+MAX(F6,0)
```

> **不要按数据块重新起算**——分块重置正是累计值错断的根源。

### 等效龄期计算表（表 C5-19-2）

| 列 | 取值 |
|---|---|
| D 试块制作日期 | 台账汇总的「成型日期」 |
| E 试块检验日期 | 台账汇总的「送检日期」 |
| F 制作日期累计温度值 | 逐日温度台账里该日的**累计温度列** |
| G 检验日期累计温度值 | 同上 |
| H 600℃·d计算值 | `G − F` |
| I 等效龄期（d） | `(送检日期 − 成型日期).days`（自然天数） |

新表按目标工作簿里模板表（默认 `Sheet1`）的格式复制：标题、表头、列宽、行高、
合并区、纸张与缩放比例一并继承，原有工作表保持不动。

> ⚠️ 台账模板的表头文字是既有的，可能与实际所取的列不一致（例如 F/G 表头写「累计温度值」，
> 实际取的是哪一列由配置 `ledger.cum_columns` 决定）。以配置为准，不要只看表头。

## 用法

### 一、重算龄期与累计温度

```bash
# 先核算看结果，不改文件
python -m c600d aging --xlsx 台账.xlsx --base 2025-11-11

# 确认无误后写回（自动备份）
python -m c600d aging --xlsx 台账.xlsx --base 2025-11-11 \
                      --write --backup 台账.备份.xlsx
```

### 二、生成等效龄期计算表

```bash
python -m c600d eqage --summary 试验台账汇总.xlsx \
                      --ledger 逐日温度台账.xlsx \
                      --target 大气测温统计表.xlsx

# 只列出会自动建哪些表
python -m c600d eqage ... --list

# 确认后写回
python -m c600d eqage ... --write --backup 统计表.备份.xlsx
```

### 参数

`aging`

| 参数 | 说明 |
|---|---|
| `--xlsx` | 台账 `.xlsx` 路径（必填） |
| `--base` | 起算日，浇注日计为第 1 天（必填） |
| `--write` / `--backup` | 写回与备份 |
| `--profile` | JSON 配置，覆盖默认表头布局 |
| `--temps` | CSV：`日期,平均温度`，补齐或替换指定日期 |
| `--sheets` | 只处理指定工作表，逗号分隔 |
| `--quiet` | 只打印汇总 |

`eqage`

| 参数 | 说明 |
|---|---|
| `--summary` | 试验台账汇总 `.xlsx`（必填） |
| `--ledger` | 逐日温度台账 `.xlsx`，提供累计温度（必填） |
| `--target` | 目标工作簿，在其中建表（必填） |
| `--write` / `--backup` | 写回与备份 |
| `--profile` | JSON 配置，覆盖表名关键字、列名等 |
| `--list` | 只列出发现的工作表名 |

### 默认表头布局（`aging`）

| 数据块 | 日期 | 平均温度 | 累计温度 | 龄期 |
|---|---|---|---|---|
| 左 | B | F | J | M |
| 右 | P | T | X | AA |

### 默认配置（`eqage`）

```json
{
  "summary": {
    "sheet_pattern": "600",
    "columns": {
      "no":   ["试件编号"],
      "part": ["浇筑部位"],
      "made": ["成型日期", "制作日期"],
      "sent": ["送检日期", "送检时间"]
    },
    "required_columns": ["no"]
  },
  "ledger": {
    "cum_columns":  { "left": "J", "right": "X" },
    "date_columns": { "left": "B", "right": "P" },
    "first_data_row": 6,
    "last_data_row": 27
  },
  "target": {
    "template_sheet": "Sheet1",
    "data_number": "02-01-C5-001"
  }
}
```

各列名支持**多个候选**，按顺序取第一个命中的列（例如有的台账写「送检日期」、
有的写「送检时间」）。工作表的发现完全按表名关键字进行，不写死楼栋名。

## 设计要点

1. **公式链不按块重置。** 左块末行 → 右块首行 → 下一张表首行，全程连续。
2. **缓存值在保存后单独注入。** `openpyxl.save()` 会清空公式单元格的 `<v>`，
   因此最后一步直接改写 `xl/worksheets/sheetN.xml`。
   ⚠️ 注入缓存值之后**不要再调用 `openpyxl.save()`**，否则缓存值会再次丢失。
3. **两个 openpyxl 的坑**（`c600d/rawxlsx.py` 专治）：
   - 样式表带非标准 `<fill>` 时 `load_workbook` 直接抛
     `TypeError: Fill() takes no arguments`；
   - **默认模式读「内联字符串」(`t="inlineStr"`) 会返回 `None`**，
     `read_only=True` 才能读出。数值「莫名丢失」时先用 `rawxlsx` 交叉验证。
4. **只读校验先行。** 默认 dry-run；发现日期断层、温度缺失、必需列找不到会直接报错退出，
   不静默产出错表。
5. **涉密信息不进代码。** 工程名称、施工单位、部位、楼栋、资料编号等一律由使用者
   通过台账与配置提供，本仓库代码不含任何具体工程信息。
