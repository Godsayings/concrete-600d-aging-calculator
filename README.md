# 600℃·d 结构实体检验温度记录 —— 龄期与累计温度自动计算

自动核算《表 C5-19-1 600℃·d 结构实体检验温度记录》中的**龄期(d)** 与 **累计温度(℃·d)**，
并把结果写成**一条跨数据块、跨工作表的连续公式链**，同时补回公式缓存值，
让 Excel / WPS 打开即显示数字。

## 为什么需要它

实际台账里这两列很容易出错，且都不容易发现：

| 典型问题 | 现象 | 后果 |
|---|---|---|
| 右侧数据块的累计温度另起一个起始值 | 累计值前后接不上 | 整块的累计温度偏低/偏高 |
| 右侧数据块的龄期是从别的工程抄来的 | 龄期突然回跳 | 之后所有龄期都错 |
| 累计温度按数据块重置 | 跨表时累计值断链 | 600℃·d 达标日算错 |
| 负温日照常累加 | 累计值倒退 | 与检验资料对不上 |
| 公式单元格没有缓存值 | 打开显示空白/0 | 看起来像没填 |

本脚本把这几件事一次做完，并给出可复核的计算依据。

## 计算口径

### 龄期(d)

自起算日（**浇注日计为第 1 天**）起的自然日差 + 1：

```
龄期(d) = (当日日期 - 起算日).days + 1
```

### 累计温度(℃·d)

```
累计温度(n) = 累计温度(n-1) + MAX(日平均温度(n), 0)
```

即 **T > 0 时累加当日平均温度；T ≤ 0 时按 0 计**。该口径下累计值**单调不减**，
不会因负温日倒退，符合冬期施工连续测温台账的通行做法。

> 这条口径不是拍脑袋定的：对真实工程台账做逐日回归后发现，账内累计值的偏差
> **每次增大都恰好发生在平均温度 ≤ 0 的那一天，且增大值恰好等于该日温度的绝对值**
> （抽验 294 个日增量：冻结口径符合 40/41 处，累加负温口径符合 253/256 处）。
> 改用该口径重算后，算出的 600℃·d 达标日与该工程检验资料中的等效龄期相互吻合。

### 写入方式

每列只把**第一格**写成数值，其余全部写成公式，保证全表一条链：

```
同表相邻行   =J19+MAX(F20,0)        （累计温度）
             =M19+1                 （龄期）
跨表相邻行   =Sheet1!J27+MAX(F6,0)
             =Sheet1!M27+1
```

> **不要按数据块重新起算**——分块重置正是累计值错断的根源。

## 用法

```bash
# 1) 先核算并看结果，不改文件
python -m c600d.cli --xlsx 台账.xlsx --base 2025-11-11

# 2) 确认无误后写回（自动生成备份）
python -m c600d.cli --xlsx 台账.xlsx --base 2025-11-11 --write --backup 台账.备份.xlsx
```

### 参数

| 参数 | 说明 |
|---|---|
| `--xlsx` | 台账 `.xlsx` 路径（必填） |
| `--base` | 起算日，浇注日计为第 1 天，如 `2025-11-11`（必填） |
| `--write` | 写回台账；不加则只核算打印 |
| `--backup` | 写回前的备份路径 |
| `--profile` | JSON 配置，覆盖默认表头布局 |
| `--temps` | CSV：`日期,平均温度`，用于补齐/替换指定日期的温度 |
| `--sheets` | 只处理指定工作表，逗号分隔 |
| `--quiet` | 只打印汇总 |

### 默认表头布局

脚本按下列布局识别数据（每个工作表有左右两个数据块，每块最多 22 行，第 6–27 行）：

| 数据块 | 日期 | 平均温度 | 累计温度 | 龄期 |
|---|---|---|---|---|
| 左 | B | F | J | M |
| 右 | P | T | X | AA |

不同表格可用 `--profile` 覆盖，例如：

```json
{
  "layout": {
    "first_data_row": 6,
    "block_rows": 22,
    "left":  { "date": "B", "temp": "F", "cum": "J", "age": "M" },
    "right": { "date": "P", "temp": "T", "cum": "X", "age": "AA" },
    "skip_sheets": ["说明"]
  }
}
```

## 补齐外部温度

缺少原始测温记录时，可从气象部门公开数据取得日平均温度
（常用近似：`(日最高气温 + 日最低气温) / 2`），写成 CSV 由 `--temps` 注入：

```csv
日期,平均温度
2025-11-11,8.5
2025-11-12,10.5
2025-11-13,7.5
```

- 表头可有可无，`#` 开头为注释。
- 只有日期、没有温度的行会被跳过（用于先占位）。

仓库里的 `tests/sample_temps.csv` **只是格式示例，不是任何工程的实际数据**，
请按自己工程的实测或公开气象数据替换。

## 设计要点

1. **公式链不按块重置。** 左块末行 → 右块首行 → 下一张表首行，全程连续。
2. **缓存值在保存后单独注入。** `openpyxl.save()` 会清空公式单元格的 `<v>`，
   因此最后一步直接改写 `xl/worksheets/sheetN.xml`。
   ⚠️ 注入缓存值之后**不要再调用 `openpyxl.save()`**，否则缓存值会再次丢失。
3. **只读校验先行。** 默认 dry-run；发现日期断层、温度缺失、日期重复会直接报错退出。
4. **涉密信息不进代码。** 工程名称、施工单位、部位、资料编号等一律由使用者
   在自己的台账和配置里提供，本仓库代码不含任何具体工程信息。
